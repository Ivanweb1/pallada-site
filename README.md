# ГК «Паллада» — вёрстка сайта

Статическая вёрстка сайта группы компаний «Паллада», перенесённая 1:1
с прототипа на Tilda — https://sitepallada.tilda.ws

Дальше страницы поштучно переносятся в Tilda через Vibe-блоки.

## Структура

```
index.html                  главная
company.html                о компании
proizvodstvokeramiki.html   производство керамики
process.html                процессы
science.html                научная деятельность
portfolio.html              портфолио
news.html                   новости
contacts.html               контакты

assets/css/style.css        токены, шапка, подвал, общие компоненты
assets/css/home.css         секции главной
assets/css/pages.css        секции внутренних страниц
assets/css/responsive.css   адаптив: 1199 / 899 / 599 / 359
assets/js/main.js           слайдер, карусели, аккордеон, масштабирование
assets/img/                 все изображения сайта (выгружены с tildacdn)

partials/header.html        общая шапка
partials/footer.html        общий подвал
tools/build.py              подставляет шапку/подвал во все страницы
```

## Как править шапку или подвал

Меняем `partials/header.html` или `partials/footer.html`, затем:

```bash
python tools/build.py
```

Скрипт обновит разметку между маркерами `<!--#header-->…<!--#/header-->`
во всех html в корне.

## Как смотреть локально

```bash
python -m http.server 4577
```

## Где смотреть онлайн

Каждый пуш в `main` или в рабочую ветку публикуется на GitHub Pages —
`.github/workflows/pages.yml`. Адрес: https://ivanweb1.github.io/pallada-site/

Один раз это нужно включить в настройках репозитория:
Settings → Pages → Build and deployment → Source: **GitHub Actions**.

## Как устроен макет

Оригинал собран на Zero-блоках Tilda с сеткой 1200 и полями 40 (контент 1120).
Zero Block с `upscale: window` пропорционально масштабирует весь макет под ширину
окна, поэтому здесь то же самое: `body { zoom: var(--zoom) }`, где `--zoom`
задаётся скриптом как `clientWidth / 1200`. Благодаря этому вёрстка совпадает
с оригиналом по геометрии на любой ширине десктопа.

## Как устроен адаптив

Десктоп (от 1200) остаётся ровно таким, каким был: тот же артборд 1200
и то же масштабирование через `body { zoom }`. Ниже 1200 скрипт отдаёт
`--zoom: 1`, и вступает `assets/css/responsive.css` — он переводит
фиксированные колонки Tilda в резиновые. Брейкпоинты:

| Ширина | Что меняется                                                        |
|--------|---------------------------------------------------------------------|
| 1199   | поля 24, колонки из пикселей в доли, шапка сворачивается в бургер,   |
|        | карусели листаются пальцем (стрелки прячутся)                        |
| 899    | почти везде одна колонка, текст слайдера ложится потоком под фото    |
| 599    | поля 16, кегль заголовков меньше, подвал и кнопки в столбик          |
| 359    | подгонка под 320: цифры в одну колонку, карточки шире по вьюпорту    |

Правки адаптива держим в `responsive.css` — десктопные файлы не трогаем,
тогда вёрстка 1:1 с оригиналом остаётся проверяемой попиксельно.

Меню на узких экранах — те же ссылки из `partials/header.html`: обёртка
`.header__menu` на десктопе обычный статичный блок, а ниже 1200 становится
выезжающей панелью (`.header.is-open`), кнопка — `.header__burger`.

Палитра и типографика:

| Токен      | Значение  | Где                                  |
|------------|-----------|--------------------------------------|
| `--ink`    | `#000000` | основной текст                       |
| `--accent` | `#8e2123` | цифры, кнопки, форма, иконки         |
| `--grey`   | `#eeeeee` | фоны секций и плейсхолдеры фото      |
| `--white`  | `#ffffff` | фон страницы                         |

Шрифты — как в оригинале: заголовочный **Tahoma** (`--t-headline-font`),
текстовый **Manrope** (`--t-text-font`, Google Fonts). Файл `tahoma.woff`
на Tilda битый (`OTS: incorrect file size in WOFF header`) и не грузится даже
на самом сайте, поэтому Tahoma подключена системно — визуально это то же,
что видно на оригинале.

## Что осталось от прототипа как есть

Эти места в оригинале ещё не заполнены — перенесены как заглушки
(серые прямоугольники `.ph` и текст-рыба), ждут контента от заказчика:

- портфолио на главной и на странице `/portfolio` — фото и описания проектов;
- лента новостей (в оригинале там стоят демо-записи Tilda на английском —
  заменены на нейтральные заглушки);
- публикации в СМИ;
- этапы на странице «Процессы»;
- фото на странице «Производство керамики»;
- образование и сертификаты на странице «Научная деятельность»;
- фото сотрудников в блоке «Команда».
